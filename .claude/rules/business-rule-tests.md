# Custom business-rule tests + variant-extension pattern (`custom_sql` 5th; `row_count_between` 6th; `unique_combination` 7th; `row_count_anomaly_by_period` 8th)

Established by issue #116 (`custom_sql`), generalised by issue #169 (`row_count_between`), extended by issue #170 (`unique_combination`), and graduated by issue #171 (`row_count_anomaly_by_period`) — this is now a **4-instance precedent** for adding a new variant to the `CandidateTest` discriminated union. Apply to any code touching any of the four variants — drafting, prompt-rendering, resolving Jinja, compiling/pruning, grading, diffing, writing to disk, or ingesting from `tests/*.sql` / `dbt_expectations.*` / `dbt_utils.*` macros.

`custom_sql` (#116) is the first test type that is a **full singular-test SELECT** (returns failing rows) rather than a parameterless/parameterised dbt schema test. `row_count_between` (#169) is the first **model-level-only** variant with a structured args contract (`minimum` / `maximum` / optional `where`). `unique_combination` (#170) is the **second model-level-only** variant — composite-key uniqueness over a `tuple[str, ...]` of columns plus optional `where`; emits as `dbt_utils.unique_combination_of_columns` YAML. `row_count_anomaly_by_period` (#171) is the **first time-bound** variant — predicts a per-period row-count band from history and flags the most-recent period when it falls outside; uses a **two-query split** (stats + violation) and a new `--as-of YYYY-MM-DD` flag to restore reproducibility at `(model, as_of)` granularity (the deliberate carve-out from Architectural Commitment #5). All four encode Architectural Commitment #1 for business rules an operator can't express with the four original built-ins: SignalForge drafts them (from `meta.signalforge.business_rules`, LLM inference, or — for `row_count_between` and `unique_combination` — `dbt_expectations.*` / `dbt_utils.*` ingest recognition), then **prunes and grades** them like everything else — an always-pass business rule is dropped, not shipped.

## The variants (#116 DEC-002; #169 DEC-001)

Two concrete subclasses of `signalforge.draft.models.CandidateTest`, both frozen, `extra="ignore"`, members of the discriminated union via `Field(discriminator="type")`, each paired with a `Strict<X>` drift mirror + a `candidate_schema_v1.json` row:

- **`CandidateTestCustomSQL`** (#116) — `type: Literal["custom_sql"]`, `sql: str` (non-empty validated), `column: str | None` (None ⇒ model-level), `rationale: str | None`.
- **`CandidateTestRowCountBetween`** (#169) — `type: Literal["row_count_between"]`, `column: None = None` (model-level only; constrained at the type level, not just by validator), `minimum: int | None`, `maximum: int | None`, `where: str | None`, `rationale: str | None`. Pydantic validators: `minimum ≥ 0`, `maximum ≥ 0`, `minimum ≤ maximum`, at-least-one-of-(minimum, maximum), `where` non-empty after strip.

**`column=None` is the model-level case** and must be special-cased AHEAD of any `test.column not in model_columns` check. With #169 in play this rule reaches BOTH the `column: str | None` shape (`custom_sql`) AND the type-fixed `column: None = None` shape (`row_count_between`). The two are equivalent at runtime — `None not in model_columns` fires a spurious violation either way — so the dispatch arm pattern is one check, two variants.

### The 6 production dispatch sites (was 5 in #116; #169 added the 6th — ingest anchor exemption)

When you add a 7th test type, audit every exhaustive `isinstance`/`match` over the union — a missing arm is a latent runtime crash, not a type error, because the union is open at runtime:

1. `signalforge.prune.compiler._compile_test` — dispatcher arm + per-variant `_compile_<variant>` helper.
2. `signalforge._common.artifact_id.model_test_args_hash` — canonical-JSON over the variant's args fields (`{min, max, where}` for #169).
3. `signalforge.diff._emitter._render_test` — YAML emission arm (kept-tier rendering); `proposed_test_files` is `custom_sql`-only.
4. `signalforge.ingest.parser._parse_named_test` — recognition of the external form (a `custom_sql` singular-test file body or a `dbt_expectations.expect_table_row_count_to_be_between` schema.yml dict).
5. `signalforge.draft.parser._validate_anchor_contract` — anchor-contract arm: skip the column-existence check for model-level variants; reuse `_check_custom_sql_type_coherence` for any `where`-fragment validation (#169 reused this verbatim from #159).
6. `signalforge.ingest.anchor.validate_anchor_contract` — **model-level test loop exemption** (NEW, #169 US-012 inline as ingest bugfix). The loop iterates `candidate.tests` (model-level) and asserts `test.column in model_columns`; for a model-level-only variant where `column=None`, this fires a spurious `"references nonexistent column None"`. The fix is one `if test.type == "<variant>": continue` early-out per model-level-only variant. Mirrors the drafter-side anchor exemption in `signalforge.draft.parser._validate_anchor_contract`.

**Sites that stay automatic — string-discriminator matching, NOT isinstance.** The grade engine's `_resolve_artifact_from_candidate` matches on `t.type == test_type` (a string compare against the catalogue key); it picks up new variants for free without an arm change. `signalforge.draft.config.VALID_TEST_TYPES` is a flat frozenset literal — adding a token to the set + the union grows the catalogue automatically. **Lesson:** when designing a new dispatch site, prefer string-discriminator over `isinstance` if the arm body is uniform across variants; reserve `isinstance` for per-variant code paths the type checker should enforce exhaustively.

## Two input paths, both in the dynamic prompt block (DEC-001)

`meta.signalforge.business_rules` (NL `str` or `list[str]`, column- and model-level) is read with the **safety-layer `meta.get("signalforge")` dict-guard pattern** (strict `isinstance(dict)`; a scalar/list under the key is config noise, dropped — never fail loud). Rules render into the drafter's **dynamic (non-cached) block**, NOT the cached system prompt — so they don't perturb the prompt-cache golden. When no rules are declared, the inferred-fallback prompt still permits `custom_sql`. `_PROMPT_VERSION` rotated when the `custom_sql` catalogue entry landed in the cached system prompt; the cache-stability snapshot moved in lockstep (`llm-drafter.md`). `exclude_tests` can name `"custom_sql"` (it's in `VALID_TEST_TYPES`).

**Numbered envelope + parser cardinality gate (#163).** Drafter instruction-following on `business_rules` was fragile on `claude-sonnet-4-6` — a plain bulleted list let the model silently skip rules and hallucinate unrelated ones (issue #163, observed in the live e2e). The fix is a **gate-over-prompt** pair (testing-signal.md §):

- **Dynamic-block envelope (DEC-009 of #163).** Each rule renders inside `<BUSINESS_RULE id="N">…</BUSINESS_RULE>` (IDs 1-indexed, body indented 2 spaces, scope prefix `(model)` / `(column X)` preserved). The envelope mirrors `<MODEL_SQL>` exactly — clearer reference targets for the LLM AND a fence-shaped surface for the prompt-injection breach guard. A rule containing the literal `</BUSINESS_RULE>` substring raises `PromptEnvelopeBreachError(envelope="BUSINESS_RULE", rule_index=N)` BEFORE any LLM call (boring substring match — no whitespace / case normalisation; opening tag alone is allowed, truncated fragments like `</BUSINESS_RUL` are allowed; only the exact closing tag breaks the fence). The error class is the same one used for `</MODEL_SQL>` — **parameterised, not subclassed** (DEC-005 of #163). Future envelopes follow the same shape: extend with a new `envelope=` value, never a new error class.
- **Parser cardinality gate (DEC-002 / DEC-006 of #163).** `_validate_anchor_contract` enforces **at-least-one-`custom_sql`-per-declared-rule**: when `business_rules` is non-empty AND `"custom_sql"` is NOT in `exclude_tests`, `custom_sql_count < len(business_rules)` appends one violation to the existing collect-all `violations` list (surfaced via `LLMOutputAnchorContractError`, CLI tier 2). At-least, not exact-equality — the LLM may legitimately decompose a complex rule into two SELECTs. The violation message names every declared rule verbatim (`repr()`-quoted with the existing `(model)` / `(column X)` prefix) so the operator sees exactly what was declared. Gate is a no-op on `business_rules=()` (preserves all existing parser-test call sites + the inferred-fallback path) and on `"custom_sql" in exclude_tests` (DEC-008 of #163). The threading mirrors #159's `model_columns_by_type` (single source of truth: built once in `signalforge.draft.schema._draft_from_request`, passed keyword-only through `parse_draft_response` → `_validate_anchor_contract`).
- **`exclude_tests=("custom_sql",)` short-circuits both surfaces.** The renderer returns `""` (don't tell the LLM to draft tests the operator forbade); the parser gate becomes a no-op. The two layers are orthogonal — the per-test `exclude_tests` filter at the parser still catches any defying `custom_sql` the LLM emits.

**No `_PROMPT_VERSION` rotation for #163.** Everything #163 changes is dynamic-block-side or parser-side; the cached system prompt is untouched. `tests/llm/test_prompt_cache_stability.py` is the load-bearing gate that pins this — touch the cached system prompt and it fails loudly.

## Lockstep `_PROMPT_VERSION` rotation when extending the catalogue (#169 DEC-012)

There are **two** independent `_PROMPT_VERSION` constants in the pipeline, each with its own cache-stability snapshot:

- **Drafter-side** (`signalforge.draft.prompts._PROMPT_VERSION`) — hash over `_SYSTEM_PROMPT + _MANIFEST_SUMMARY_TEMPLATE + _DATA_SECTION_TEMPLATES_JSON`. Rotates when `_TEST_CATALOGUE_LINES` grows (adding a 6th variant; per `llm-drafter.md`). Pinned by `tests/llm/test_prompt_cache_stability.py::_EXPECTED_PROMPT_VERSION`.
- **Grade-side** (`signalforge.grade._PROMPT_VERSION` analog) — hash over the grade system prompt + rubric criterion list. Rotates when any of the 4 default criterion texts changes (#169 DEC-009 refined a criterion to score vacuous row-count bounds). Pinned by the grade-side cache-stability snapshot (parallel module).

Two surfaces, two `_PROMPT_VERSION`s, two cache-stability snapshots — all four MUST move in the same commit when extending the catalogue. Per memory `ralph-serialize-shared-registry-beads`, **serialize the two beads** when they land in parallel Ralph runs: two workers fighting the same kind of golden update will collide. **Don't conflate the two — a catalogue extension (drafter) is independent from a rubric refinement (grade); a variant addition usually requires both.**

## `where`-clause sqlglot type-coherence — reuse, don't fork (#169 DEC-004, DEC-006)

`row_count_between.where: str | None` is a SQL fragment, so it inherits #159's type-coherence problem on `custom_sql`: the LLM may emit `where: "start_station_id <> end_station_id"` where the two columns are different types. The parser arm threads `model_columns_by_type` (built once in `signalforge.draft.schema._draft_from_request`) through `_validate_anchor_contract` and **reuses `_check_custom_sql_type_coherence`** (the #159 helper) on the composed statement — no new sqlglot helper, no new parser surface. Skip-when-uncertain posture preserved. sqlglot imports stay confined to `signalforge.draft.parser` (the import-guard scan from #159 still passes; only one consumer in v0.3).

**Lesson — `where`-fragment validation seam (DEC-005 of #169):** compose `SELECT COUNT(*) FROM <table_ref> WHERE <where>` THEN call existing `validate_test_sql` on the **full statement**. Don't write a new `validate_where_fragment` helper. A `where` rejected by safety routes via `_InvalidIdentifier` → `kept-without-evidence` (`why="identifier rejected by SQL safety check"`). Same surface as `custom_sql` rejection — one path, two callers.

## Bounded Jinja resolution — NO Jinja engine (DEC-004, DEC-005)

`signalforge.manifest.resolve_template_refs(sql, model, manifest) -> str` substitutes `{{ this }}` (→ `model.resolve_this()`), `{{ ref('m') }}` / `{{ ref('pkg','m') }}` / version forms, and `{{ source('s','t') }}` to qualified names via the manifest source registry + `resolve_ref`/`resolve_source` (also #116). Control-flow Jinja (`{% … %}`, `{{ var() }}`, `{{ env_var() }}`, macros) and any residual `{{ }}` after substitution are **rejected loudly** (`UnsupportedJinjaError`/`TemplateResolutionError`, in the existing `manifest/errors.py` — do NOT add a new `errors.py`, scan-7 asserts exactly 11). The resolver lives in the **manifest layer** (stage-0, no logging) so both prune and ingest consume it without a cross-stage import.

## Prune-compile: resolve → safety-check → wrap, dialect-driven (DEC-003/006/008/009)

`prune.compiler._compile_custom_sql` ordering is load-bearing and security-relevant: **resolve Jinja first, then `validate_test_sql` on the RESOLVED sql, then wrap.** The adapter re-validates before running (belt-and-braces). No `count(*)` pre-wrap in the compiler — it returns the failing-rows SELECT; the adapter owns `SELECT COUNT(*) AS failures FROM (<sql>) AS t` (matching the built-ins; pre-wrapping double-counts). Dialect-driven via `Dialect.quote_char`; **no `google.cloud` import under `prune/`.**

- **Single-table** (no `JOIN` after literal-stripping) → sample-CTE wrap.
- **Multi-table** → full-scan, bounded only by `maximum_bytes_billed` (sampling a join is semantically wrong; DEC-006). The bytes cap is the sole guardrail — documented operator tuning point.
- **Conservative-bias routing — never raise out of the compiler, never add a 6th `DropReason`.** Safety-reject / unsupported-Jinja / ambiguous-ref → `_InvalidIdentifier` → `kept-without-evidence`; unresolvable `ref()`/`source()` (manifest-absent target) → `_RequiresFutureData` → `requires-future-data` (the relationships-missing-target precedent). The engine matrix (`_decide_from_test_result`) is test-type-agnostic and routes `custom_sql` generically; over-bytes-cap is just a per-test `WarehouseError` → `kept-without-evidence`.

### Materialised-sample substitution — TWO directions, READ THIS (#116 QG bug + #169 QG bug)

The materialised-sample contract (#22) is **per-test-type-aware**. Two distinct failure modes, both caught only at QG, both load-bearing:

**Direction 1 — `custom_sql` (#116 US-019 / QG fix): bypass-to-temp-table substitution.** A test type that builds its own `FROM` clause (rather than from the passed `table_ref`) will silently bypass the materialised temp table. Under the default `sample_strategy="materialised"` + `scope="sample"`, the engine materialises a temp table and calls the compiler with `table_ref = <temp table>`. The four original built-ins FROM `table_ref`, so they read the temp table for free. `custom_sql` resolves `{{ this }}` to the model's **source** table, so its compiler arm MUST explicitly rewrite the model's own qualified name → the quoted `table_ref` everywhere. Missing this = full-scanning production under the cost-saving strategy. Pinned by a test asserting the compiled SQL references `_SESSION._sf_sample_*` and never the source table.

**Direction 2 — `row_count_between` (#169 US-007a / QG fix): bypass-the-substitution-itself.** A test type that queries **metadata / aggregates** (`COUNT(*)`, `MAX`, `MIN`, `SUM`) rather than row-level data must NOT consume the substituted `table_ref` — a `COUNT(*)` against a materialised sample returns the **sample size** (e.g. 100_000), not the model's real row count; bounds checked against sample size are semantically meaningless. The fix lives in the engine, NOT the compiler: `signalforge.prune.engine` computes a `per_test_table_ref` that resolves to the **source** for `row_count_between` and to `compile_table_ref` (the substituted temp) for every other variant. The COUNT(*) against the source is a single cheap aggregate scan even on petabyte tables, so there's no cost argument for routing through the temp table. Under `prune.scope="sample"` + `sample_strategy="oneshot"` the bypass is deliberate too — a sampled COUNT(*) is semantically wrong by the same argument. Pinned by `tests/prune/test_engine.py::test_prune_tests_row_count_between_under_materialised_references_source_not_temp_table`.

**Decision rule for the next variant.** When adding a 7th test type, ask first: **what does this test's compiled SQL query — row-level data, or metadata/aggregates?**

- **Row-level (sample is faithful):** consume `table_ref` as-is; if the variant builds its own `FROM` (`{{ this }}` resolution), substitute the source qualified name → `table_ref.qualified_name` per Direction 1.
- **Metadata / aggregate (sample is semantically wrong):** override `per_test_table_ref` to the source in the engine's per-test loop (the #169 pattern). Document the divergence in `docs/prune-ops.md` + the variant docstring + a dedicated pinned test.

**Any future warehouse-substituting strategy (or new self-FROM / new aggregate test type) must carry the matching substitution + pinned test.** Snapshot equality alone certifies shape, not semantic correctness — pin the source-vs-temp routing with a behavioural assertion, not just a snapshot.

## On-disk artifact: proposed `.sql` files for `custom_sql`; YAML block for `row_count_between` (#116 DEC-010/011; #169 DEC-002)

**Per-variant emission form** — the diff emitter picks the surface based on the variant, not via flag-gating:

- **`custom_sql`** — standalone `tests/*.sql` singular-test files, NOT `schema.yml` blocks. `DiffReport.proposed_test_files: tuple[ProposedTestFile, …]` carries them; `audit_schema_version` bumped 2→3 (#116). The diff emitter SKIPS `custom_sql` in the YAML emitter and routes it to `proposed_test_files`.
- **`row_count_between`** — `dbt_expectations` YAML block under the existing `tests:` list: `{dbt_expectations.expect_table_row_count_to_be_between: {min_value: N, max_value: M, where: "..."}}` (omitting null fields). No `.sql` fallback in v0.3; no `packages.yml` detection. Operators without `dbt-expectations` installed see the YAML, get a clear `dbt parse` error, and either install or remove. The 6th fail-closed writer stays `custom_sql`-only.

For `custom_sql`, renderers show new-file hunks with the unconditional ANSI-strip + dynamically-sized markdown fence on the SQL body (the SQL is user/LLM content). Filenames come from `diff._test_file_writer.anchor_to_filename` (slugs every component to `[A-Za-z0-9_]` — cannot escape `tests/`). Writing is the project's **6th fail-closed writer** (`_FAIL_CLOSED_WRITER_MODULES`, scan 8): size-check → symlink-hardened canonicalise → `O_WRONLY|O_CREAT|O_TRUNC|0o600` → short-write loop → fsync, no `except` around write/fsync. `DiffTestFileWriteError`/`DiffTestFileRecordTooLargeError` are tier-3 in the exit-code table.

**Decision rule for the next variant.** The fail-closed writer is expensive ceremony (6 mechanical safety layers + a scan-8 entry); reach for it only when the artefact is genuinely a standalone file (singular-test SQL, custom JSON). Variants representable as a schema.yml dict body — including `dbt_expectations.*` and `dbt_utils.*` macros — stay in the YAML emitter. **Default to YAML; promote to `proposed_test_files` only on a real artefact need.**

## CLI: `generate --write --force` + read-only `prune-existing` (DEC-010/013)

`generate --write` writes proposed `.sql` via `write_test_file`. The `-- signalforge:generated <hash>` header marker is the ownership signal: a NEW file is written; a marked file is overwritten ONLY with `--force`; an **unmarked (hand-authored) file is NEVER overwritten, even with `--force`** (refuse + WARNING). `prune-existing` stays read-only (#105) and gains `--tests-dir` (default `<project>/tests`): it ingests existing `tests/*.sql` via `ingest.read_test_files(..., existing=<schema candidate>)`, dedupes by `(model, "custom_sql", sql_hash)`, and prunes them alongside schema.yml tests in one run. No `--write` there.

## Ingest: stage-0 reader, closed SkipReason (#116 DEC-013; #169 DEC-007)

Two recognition paths, both stay within the closed 3-value `SkipReason` Literal — every new variant reuses an existing reason, never grows the enum:

- **`custom_sql` (#116):** `ingest.read_test_files` enumerates `tests/*.sql`, resolves refs to associate each test to the model it references (unrelated files are simply not included — NOT skip-recorded), and records unsupported-Jinja files as `SkippedTest(reason="malformed-supported-test")`.
- **`row_count_between` (#169):** `signalforge.ingest.parser.parse_test_entry` gains a recognition arm for `dbt_expectations.expect_table_row_count_to_be_between` with full args: `min_value`, `max_value`, AND the `where` config key. Maps to `CandidateTestRowCountBetween(minimum=..., maximum=..., where=...)`. Malformed args (missing both bounds, non-int values, `min_value > max_value`, non-string `where`, column-scoped usage which isn't representable on the variant) → `SkippedTest(reason="malformed-supported-test")`. A different macro like `expect_table_row_count_to_equal` stays `SkippedTest(reason="custom-or-generic-test")` (no change to existing behaviour).

The **anchor exemption** in `signalforge.ingest.anchor.validate_anchor_contract` is the 6th dispatch site (see § "The 6 production dispatch sites" above) — model-level-only variants short-circuit the column-existence check.

**Field-naming seam on either side of ingest+diff.** Pydantic carries `minimum` / `maximum` (prefix-free, matches the existing `values` / `to` / `field` precedent); dbt-expectations uses `min_value` / `max_value`. The mapping seams are exactly two functions — `_parse_row_count_between` in ingest (inbound), `_render_test` arm in diff emitter (outbound). Don't push the dbt-expectations naming into the internal model; don't render the Pydantic field name into the YAML block. Cleaner separation than picking one and apologising on the other side.

No logging, no audit writer in either path (stage-0; `ingest-layer.md`).

## Testing variant paths

**Engineer determinism by rule semantics, not LLM SQL bytes.** A tautology over the model's own rows is mathematically always-pass → dropped; an engineered violation is guaranteed failing-rows → kept. Two precedents:

- **`custom_sql`:** multi-table tests need a real two-distinct-ref JOIN (a `{{ this }} JOIN {{ this }}` self-join may collapse to the single-table classifier) AND an assertion on the dispatched SQL shape (no `WITH sample`) — asserting only the routed decision lets a sampling regression pass (the #116 QG gap).
- **`row_count_between`:** an always-pass test is `minimum: 0, maximum: huge`; an engineered-failure test is `where: "false"` + `minimum: 1` (COUNT = 0 against a non-empty table → mathematically guaranteed failing-rows → kept).

**Pin the engine-routing test, not just the compiler snapshot.** When a variant requires a per-test engine override (the #169 `per_test_table_ref` source-vs-temp bypass), pin the override with an assertion on the dispatched SQL — `test_prune_tests_row_count_between_under_materialised_references_source_not_temp_table` checks the compiled SQL references the source table and NEVER `_SESSION._sf_sample_*`. A snapshot of the compiler output alone certifies shape, not the engine routing — the bug lived in the engine, not the compiler. Mirror this for any future metadata/aggregate variant.

**Fixture injection patterns.** The e2e fixture injects `meta.signalforge.business_rules` into the per-run `tmp_path` manifest copy so it stays decoupled from the `init-demo` byte-parity gate. For `row_count_between`'s e2e (#169 US-012), the same `tmp_path` isolation primitives (`copy_fixture_to_tmp` + an `inject_model_row_count_rules` analog of `inject_model_business_rules`) apply — see `testing-signal.md` § "Per-test provider overlay" for the seam shape.

## #170 lessons worth carrying forward

Five durable conventions surfaced during #170's QG that the next variant-extension should pre-empt:

1. **Two engine conditionals, not one** — sample-mode source override has TWO sites: `all_bypass_to_source` (short-circuit when EVERY candidate bypasses) AND `per_test_table_ref` (per-test override inside the loop). The US-005b worker discovered this; both sites grow in lockstep when adding a metadata-bypass variant. Single-variant tests only exercise the short-circuit; a mixed-candidate test (1× bypassing + 1× not-bypassing) is **load-bearing** for the per-test arm (see `tests/prune/test_engine.py::test_prune_tests_mixed_candidates_per_test_override_routes_unique_combination_to_source` — the routing pin Pass 3 of #170's QG flagged was missing).

2. **`__repr__` redaction is not enough; Pydantic v2 has `__repr_args__` / `__rich_repr__` / `__pretty__`** — DEC-013 of #170 added `__repr__` redaction for 3 variants carrying LLM-emitted text (`where` / `sql` / `rationale`). QG Pass 1 empirically verified that `rich.print()` / `devtools.pretty()` / `pprint` reach through `__repr_args__()` rather than `repr()` and would otherwise still leak. Add `__repr_args__` overrides in lockstep so all three structured-debug hooks inherit the filter. Tests must exercise `instance.__repr_args__()` directly (the `repr()`-only test misses the leak).

3. **SORT a tuple-shaped arg in the canonical hash, never preserve order** — DEC-011 of #170 made the `columns` tuple sort before hashing in `_common.artifact_id.model_test_args_hash`. Pinned by `tests/diff/test_artifact_id.py::test_unique_combination_columns_sorted_before_hashing` + the three-column permutation test. Rationale: `(a, b)` and `(b, a)` describe the same constraint (GROUP BY result-row identity). Mirrors the `accepted_values.values` precedent. The diff EMITTER preserves declared order; only the hash sorts (split contract).

4. **mkdocs anchor corruption from ATX `##` inside a fenced code block** — the `## BUSINESS RULES` literal inside a ` ```text ` fence in `docs/draft-ops.md` (originally added by #163) silently broke 14 of 20 H2 anchors downstream of the block. mkdocs's anchor generator scans for ATX headings without respecting code-fence boundaries; the fix is to use an indented (4-space) code block, which IS respected. Worth pre-empting in any new ops doc that needs to show a literal `##` heading in an example.

5. **Drive-by formatting reveals a pre-merge gap** — three of #170's workers (US-005a, US-007, US-002) all independently "drive-by formatted" `tests/draft/test_parser.py` despite US-004's own validation having passed `ruff format --check .`. Pre-merge `ruff format --check` against the LATEST `dev` HEAD (not just the worker's worktree HEAD) would catch this class of merge-induced format drift. A maintainer note in the closeout flow: re-run `ruff format --check .` after merging each worker branch, not just at the worker's own commit time.

## #171 lessons worth carrying forward

Issue #171 (`row_count_anomaly_by_period`) is the **4th instance** of the variant-extension precedent — the pattern is now well-trodden mechanics. Six durable conventions surfaced during #171 that the next variant-extension should pre-empt:

1. **Time-bound primitives need an explicit reproducibility carve-out, not silent acceptance.** `row_count_anomaly_by_period` is the first primitive whose decision is time-bound (same SQL + same warehouse data + different evaluation day = potentially different pass/fail). #171 threads `--as-of YYYY-MM-DD` through CLI → `prune_tests` → compiled SQL → `PruneEvent.as_of` AND `PruneDecision.as_of`. Default-to-`date.today()` + INFO-log-the-resolved-value (DEC-001). Reproducibility restored at `(model, as_of)` granularity instead of `model` alone. The carve-out is documented openly in README / drafter-catalogue / prune-ops; don't hide it. **For any future time-bound primitive, follow this shape verbatim** — never let the corpus drift day-over-day for reasons unrelated to the model.

2. **Cross-stage numerical state lands as a typed `AnomalyTestStats` discriminated union, not a free-form dict.** When a primitive needs prune-emitted statistical state visible to the grader (or diff renderer, or future v0.x stage), define a method-tagged Pydantic discriminated union (`Annotated[MadStats | ZscoreStats | PercentileStats | MinMaxStats, Field(discriminator="method")]`) at `signalforge.prune.stats`. Each subclass `extra="ignore"` + paired `Strict*` drift mirror + fixture row. Field on BOTH `PruneDecision` (in-memory access) AND `PruneEvent` (audit-of-record), with custom `__repr__` / `__repr_args__` redaction. Future primitives needing cross-stage state inherit the seam — don't reinvent.

3. **Two-query split is the cold-start template for stats-dependent primitives.** When a primitive's verdict depends on per-test statistical state, compile into TWO SQL strings (stats + violation). Engine runs Query 1 first, parses into the typed stats object, checks cold-start threshold; if cold (`n < min_samples_per_bucket`), emits `kept-without-evidence` with structured `why="insufficient history: N/M periods"` and **SKIPS Query 2** (no warehouse call). Otherwise runs Query 2 (the standard violation path). **DropReason stays 5-valued** — cold-start NEVER grows the enum (mirrors the conservative-bias routing template from `prune-engine.md`).

4. **DEC-010 — DEC choices with cross-variant blast radius are explicit, CHANGELOG-obligated, and require the load-bearing mixed-candidate test for EVERY affected variant.** #171's DEC-010 tightened the bypass-under-`oneshot` semantics for `row_count_between` + `unique_combination` (was: materialised only). This was Q10 in Phase 1 scoping, chosen explicitly — tighter semantic floor at the cost of touching two prior variants' behavior. Three obligations: (a) `CHANGELOG.md` § Changed entry with verbatim language; (b) mixed-candidate test for each affected variant (1× metadata-aggregate + 1× row-level under the now-bypassed strategy); (c) the centralised `_test_requires_source_table(test, sample_strategy)` helper replaces inline isinstance at BOTH engine sites (avoids the two-conditional drift class #170's QG Pass 3 caught).

5. **`Dialect` graduates declarative SQL fragments per family-of-operations, never `if dialect.name == ...`.** #171 added 5 new date-arithmetic fragment fields to `Dialect`: `date_trunc_expr_template`, `interval_expr_template`, `extract_dow_expr_template`, `dow_sunday_index`, `percentile_cont_expr_template`. BigQuery defaults preserve byte-equality on the 7 existing variants. Snowflake overrides. POSTGRES_DIALECT inherits BQ defaults until its adapter lands. The compiler reads these directly — `tests/prune/test_compiler_import_guard.py` still gates the no-SDK-import rule. **Pattern for any future primitive needing date math, percentile math, or any other dialect-divergent SQL fragment**: declare a field on `Dialect`, set BQ + Snowflake values, never name-branch.

6. **Per-site `_VARIANTS_PENDING_DISPATCH_ARMS` dict + parallel-bead orchestration.** #171's US-003 introduced a single scaffolding set to keep the dispatch-exhaustiveness test green while the 6 dispatch-arm beads landed in their own commits. US-004 + US-008 independently restructured it to a per-site dict keyed by site number (1–6) so each bead can mark its OWN site as landed without waiting for siblings. **Three orchestrator-only lessons**: (a) when two parallel beads independently arrive at the same scaffolding restructure with different naming, merge conflicts are coordination artifacts (not logic conflicts) — orchestrator resolves by picking HEAD's convention and applying the late bead's intent (clear the relevant site's pending set). (b) Workers can't predict their sibling's naming choice; the conflict shape is benign and the merge is mechanical. (c) Post-all-beads-landed, the dict stays as scaffold for the NEXT variant addition — every entry empty until repopulated for the next #N's beads.

7. **Adapter graceful-degrade pattern for vendor-specific stats queries.** #171 added `WarehouseAdapter.run_stats_query(sql) -> tuple[dict, ...]` ABC method per the `materialise_sample` / `estimate_query_bytes` precedent. Default raises `StatsQueryNotSupportedError(WarehouseError)` (tier 3 in `_EXCEPTION_TO_EXIT_CODE`); BigQuery overrides; Snowflake / Postgres stubs inherit the degrade. Engine catches as any `WarehouseError` and routes to `kept-without-evidence` per the conservative-bias contract. **For any future primitive requiring a vendor-specific data-shape query**: mirror this pattern verbatim. The non-supporting adapters degrade gracefully; the primitive ships behind a typed error the operator can act on.
