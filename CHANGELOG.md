# Changelog

All notable changes to SignalForge are documented here. The format is loosely based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project follows [PEP 440](https://peps.python.org/pep-0440/) for version numbering.

## [Unreleased]

### Added

- **Grade stage drives to 100% scored — or fails loud — by default (#202).** A 10-way concurrent grade fan-out previously retried 429s with blind backoff and ignored rate-limit headers, bursting past the per-minute cap and degrading dozens of pairs to `GradeLLMError` (the #179 retest measured 70/408 and 34/220 ungraded). Three new mechanisms close this: (1) a **rate-limit-aware adaptive throttle** — a shared, header-honouring limiter (`retry-after` / `anthropic-ratelimit-*` via a SDK-confined `RateLimitBudget` provider seam, DEC-012) plus an `AsyncConcurrencyGate` whose cap tracks the limiter's effective concurrency (÷2 on a 429, +1 on a clean completion, bounded `[1, max_concurrent_calls]`, shared across the grade `TaskGroup` via a `ContextVar`); wired into both `call_llm` and `call_llm_async`. (2) An **always-on bounded transient-recovery sweep** — degraded `score=None` pairs are re-graded sequentially with cool-down under their own `asyncio.timeout(sweep_budget_seconds)`, reusing the #189 cache so only failures are re-touched (`sweep_max_rounds=3`, `sweep_budget_seconds=300`). (3) A **fail-loud completeness gate** — new `GradeConfig.require_complete: bool = True` plus the `--require-complete` / `--no-require-complete` CLI flag (no-clobber `default=None` sentinel; 6-surface parity). When a non-exempt pair survives recovery, the new tier-2 `GradeIncompleteError` names the exact ungraded pairs and exits 2. Only *intentional* operator ceilings (`max_grade_*`, an explicit `total_budget_seconds`) are exempt — a default-scaled-budget trip is never silently incomplete. The **bias-to-completion posture** (DEC-210) is now documented in `docs/grade-ops.md` + the rules: incompleteness is only ever a deliberate operator choice, never a passive default. Live metered retest (2026-06-05) reached 412/412 and 220/220 scored, `aggregate_complete=True`, and was *faster* than the non-adaptive pass (pacing the fan-out at the provider's rate cuts 429-retry churn).
- **Grade-stage budget scales with the work + opt-in cost ceilings (#198).** The flat 300 s wall-clock budget was sized for the pre-#186 sequential era and undercounted realistic concurrent work by ~3–4×. The grade budget is now `effective = budget_base_seconds(60) + budget_per_pair_seconds(20.0) × ceil(num_pairs / max_concurrent_calls)` — grounded in the #179 baseline (~10 s/Sonnet-judge-call at ~2.25× headroom). `GradeConfig.total_budget_seconds` is reinterpreted as an **optional absolute cap** (`int | None`, default `None`); `effective = min(scaled, total_budget_seconds)` when set, preserving v0.1 semantics for pinned configs. Three new opt-in cost ceilings — `max_grade_calls` / `max_grade_cost_usd` / `max_grade_tokens` (all `None` = off) — stop scheduling new pairs when whichever trips first; remaining pairs **degrade** (never raise) with a reason naming the ceiling, so there are no new typed errors, no exit-code/AST-scan churn, and no `audit_schema_version` bump from this change. Cost is resolved once up front via `signalforge.llm.pricing` (fail-fast on an unpriced SKU rather than mid-fan-out). The budget WARNING field is renamed `total_budget_seconds` → `effective_budget_seconds`; a new `grade ceiling exceeded` WARNING names the tripped ceiling. See `docs/grade-ops.md` § Configuration.
- **Bulk-mode shared cached prefix for `signalforge generate --select` + `--cache-scope` flag (#188).** Across a multi-model `--select` batch the LLM drafter's Anthropic prompt-cache hit rate goes from **0% → ~95%** — previously each model paid `cache_creation` from scratch because the cached block was per-model. New `DraftConfig.cache_scope: Literal["per-model", "project"] = "per-model"` (`llm:` namespace, drift-detected) restructures the cached block into a **project-level shared prefix** that is byte-identical across the batch (compressed whole-project `name (N cols)` summary + project-wide business rules in a `<PROJECT_MANIFEST>` envelope with a boring-substring breach guard; deterministic `sorted(unique_id)` → column → global-rule total order is the cache-hit precondition), so models 2..N hit `cache_read` (~12× cheaper input-side). Per-model detail moves to the uncached dynamic block. New CLI `--cache-scope {per-model,project}` flag auto-promotes to `project` on a `--select` of ≥ 2 models (precedence: flag > non-default YAML > auto-promote). Oversize project prefix falls back to per-model and retries once (DEC-006); an envelope breach still fails closed (security, deliberately distinct from the size fallback). Single-model positional output is byte-identical to pre-#188. OpenAI/Gemini are no-ops (no prompt caching); Anthropic Sonnet/Opus need ≥ 1024 cached tokens, Haiku ≥ 2048. See `docs/draft-ops.md` § Bulk-mode shared cache and `docs/cli-ops.md` § `--cache-scope`.

### Changed

- **Grade `audit_schema_version` bumped 2 → 3 + `max_retries_429` default 3 → 6 (#202).** The grade audit event and `GradingResult` gain a structured `degrade_reason_type` discriminator (`Literal["transient", "budget", "ceiling"] | None`) replacing fragile reason-string matching — the sweep and completeness gate key on it to tell a recoverable transient failure apart from a deliberate operator ceiling. The field defaults to `None` and `audit_schema_version` stays typed `int` (not `Literal`), so v1/v2 grade JSONLs still round-trip. The default 429-retry budget rises 3 → 6 (#202 US-008 / DEC-209) so the adaptive throttle has more headroom before a pair degrades.
- **Drafter `_ROW_COUNT_BETWEEN_SCOPE_INSTRUCTION` lands + `#170` prose-test parity backfill (#183).** The `row_count_between` primitive was already complete end-to-end as of #169, but the DEC-012 narrative scope-instruction block — the cautionary prose steering the drafter toward meaningful bounds and away from vacuous `minimum=0`/no-`maximum` shapes — never shipped with it. This adds it, rotating `_PROMPT_VERSION` in lockstep (the cached manifest-summary golden is untouched, so the cache-hit precondition holds). Also backfills the prose tests for `#170`'s `_UNIQUE_COMBINATION_SCOPE_INSTRUCTION`, which shipped without them. Operators upgrading from a cached prior version pay a one-time prompt-cache miss on their next run before the new prompt warms.
- **Grade cache now defaults OFF — `GradeConfig.cache_enabled` flipped `True → False` (#197).** The persistent grade cache shipped in #189 (same v0.6 line) defaulted on, but its key mixes `artifact_text_hash` — and the drafter produces fresh artifact text on every `generate` run, so the cache almost never hits on the common path and just litters `.signalforge/grade-cache/*.json` files for no speedup. The default is now `False`; operators who genuinely benefit (re-grading identical artifact text — e.g. rubric calibration, a `prune-existing`-style fixed-input loop, or a future draft-caching feature) opt in via `grade.cache_enabled: true` in `signalforge.yml`. With the default off, `signalforge generate --no-cache` is a no-op unless the operator has explicitly enabled the cache. The cache mechanics (content-addressed key, fail-soft writes, degrade-never-cached) are unchanged — only the default flipped. See `docs/grade-ops.md` § Grade cache.

### Docs

- **`prune-existing` / column-level tests now document the `schema.yml` prerequisite (#204).** Clarifies that column-level tests require a `schema.yml` declaring the model's columns, and documents how to generate one (e.g. via `dbt-codegen`) before running SignalForge against an existing project.

### Added

- **`signalforge generate --no-grade` + `--no-cache` flags + persistent grade cache + `signalforge cache clear --grade` subcommand (#189).** Two operator UX wins for the grade-heavy iteration loop.
  - **`--no-grade`** (DEC-001) — bare boolean on `signalforge generate` that skips the grade stage entirely. Drafter + safety + prune + diff still run; `grading_report=None` flows through to `render_diff` (already supported), so the diff renders without the `flagged` tier. No `grade.jsonl` / `grade.json` produced. Progress honestly re-numbers to `[N/4]` (no `[X/5] grade: skipped` line) — the orchestrator resolves `total = 4 if no_grade else 5` once at startup.
  - **`--no-cache`** (DEC-002) — bare boolean that flips `grade_config.cache_enabled = False` for one run (cache lookup AND write bypassed; existing cache files untouched). Per-run escape valve for debugging / calibration / forced re-grade. Precedence: `--no-grade` implicitly wins when both are set (no grade calls = no cache reads/writes).
  - **Persistent grade cache** — content-addressed JSON cache at `<project>/.signalforge/grade-cache/<16-hex>.json` (`0o600`, lazy-mkdir). Cache lookup runs synchronously in the sync prefix of `grade_artifacts`, BEFORE the #186 asyncio TaskGroup; cache hits resolve without acquiring the semaphore. Cache misses run the LLM, then `write_cache` persists the verdict (fail-soft per DEC-005 — `OSError` / oversize / `FileExistsError` race → one WARNING + no-op; the live grade never aborts). Five-part cache key recipe: `blake2b-8(criterion_prompt_hash + artifact_text_hash + provider + model + prompt_version_template)` (DEC-004); cleanly invalidates on each axis. Degraded results (`score=None`) NEVER land in the cache (DEC-007 — caching a degrade would silently replay the failure forever). 16 KB pre-write size cap (DEC-006). Cache files inherit `.gitignore` coverage via the existing `.signalforge/` blanket. Cache-hit `GradeEvent`s carry `cache_hit=True` + zero token counts; cost rollup arithmetic correctly attributes $0.
  - **`signalforge cache clear --grade`** subcommand (DEC-015) — wipes `.signalforge/grade-cache/` via `shutil.rmtree`. Symlink-hardened with two layers (#189 QG Pass 1 Finding 2): suffix containment (canonical path ends with `.signalforge/grade-cache`) AND project-anchor containment (canonical path lives inside the resolved `project_dir`). Idempotent on a missing directory. Operator handle for "I edited the rubric, purge stale cache." Nested-subparser shape documents a deviation from `cli-layer.md` § "flat-per-subcommand modules" justified by forward-compat for `cache stats` / `cache list` / `cache clear --drafter`.
  - **`GradeConfig.cache_enabled`** (DEC-016) — config-file knob under `grade:`; `extra="forbid"` so typos like `cache_enable: false` fail loud at config load. (Shipped defaulting to `True`; **#197 flipped the default to `False`** later in the same v0.6 line — see the `### Changed` entry above. Opt in via `grade.cache_enabled: true`.)
  - **New cache-lookup key-verification gate (#189 QG Pass 1 Finding 1)** — `lookup_cache` recomputes the 5-part key from the loaded record's stored hashes and compares to the lookup key; on mismatch (corrupt or hostile file body) returns `None` + INFO log. The forensic-hash trail is load-bearing, not self-attesting. Closes the cache-poisoning gap.

### Changed

- **`GradeEvent` gains `cache_hit: bool = False` field + `audit_schema_version` 1 → 2 (#189).** New audit-event field carries the cache-hit signal into the durable JSONL so cost-rollup + post-run forensics can distinguish cache hits from live grades. v1 audit JSONLs still round-trip via the `audit_schema_version: int` type (US-001 flipped it from `Literal[1]` to `int` so version bumps preserve replay) + the `cache_hit: bool = False` default + `extra="ignore"` on the production model. New v2 strict drift mirror (`StrictGradeEventV2(extra="forbid")`) paired with a v2 fixture exercising both `cache_hit` values; v1 fixture stays as the backward-compat anchor.

### Fixed

- **Drafter mis-scoped `row_count_anomaly_by_period` to date columns on models with audit timestamps (#184).** On every model carrying audit-timestamp columns (`creation_ts`, `update_ts`, `loaded_at`, `created_at`, `event_date`, `partition_date`, `LOAD_TIMESTAMP` — the Intuit `PREDEFINED_AUDIT_COLUMNS` convention) the LLM emitted `row_count_anomaly_by_period` *inside* the date column's `tests:` list rather than at model scope. Because the variant is type-level model-only (`column: None = None`), the candidate failed the anchor contract with the confusing "model-level test references nonexistent column None" — the whole `signalforge generate` run aborted (CLI exit 2). Reproduced 3/3 on the first three Phase B candidates of the #179 retest. The fix has two complementary levers: (1) **prompt-side** — `_ROW_COUNT_ANOMALY_SCOPE_INSTRUCTION` was rewritten to explicitly teach model-level placement (a cooperative drafter avoids the mistake); `_PROMPT_VERSION` rotated `e568fb3e4602e465 → 32d33f14a3a57060`. (2) **parser-side belt-and-braces** — `_validate_anchor_contract` now detects a column-scoped emission of any model-only variant (`row_count_anomaly_by_period` / `row_count_between` / `unique_combination`), silently re-attaches it to model scope, emits one operator-visible `_LOGGER.warning` ("parser re-attach: …" with 5-key JSON payload), and records the reshape in a new `LLMResponseEvent.parser_reshaped: tuple[ReshapeRecord, ...]` audit field for the durable forensic trail. Re-attached tests' args (`date_column` / `where` / `unique_combination.columns`) are also re-validated against `model_columns` to preserve the "fail loud on hallucinations" contract — a re-attached `row_count_anomaly_by_period(date_column="phantom_col")` surfaces as an anchor-contract violation instead of silently degrading to `kept-without-evidence` at prune. The `exclude_tests` kill-switch always wins (a column-scoped emission of an excluded variant is still rejected as the standard exclude violation, never re-attached). **Operator action:** if you added `llm.exclude_tests: [row_count_anomaly_by_period]` to your `signalforge.yml` as a pre-fix workaround, remove it — the fix renders the workaround unnecessary, and leaving it in place would suppress a now-correct test variant. See `docs/draft-ops.md` § "Parser re-attach for mis-scoped model-only variants" and the matching `### Changed` entry below for the audit-schema bump.

### Added

- **Wide-table safety audit: symbol-table compression + chunked records (#185).** The safety audit JSONL now keeps wide-table models (tens to hundreds of redacted columns) under the 4000-byte POSIX-atomic-append cap. Two new `AuditEvent` fields replace the per-column `redactions: tuple[RedactionRecord, ...]` payload: `redactions_by_reason: dict[RedactionReason, tuple[str, ...]]` (keys = redaction reason literal; values = sorted tuples of hashed names) and `column_name_map: dict[str, str]` (hashed name → real column name, preserving the reviewer mapback path). When the serialised event still exceeds 4000 B, the writer splits it across multiple JSONL lines correlated by three new fields: `audit_id` (16-hex `blake2b` correlator; deterministic per source event), `chunk_index` (0 for the header chunk, ≥ 1 for continuations), and `chunk_count` (total chunks for this event). Three legal record shapes: non-chunked (all metadata populated, correlation triple `null`), chunk header (`chunk_index=0`, empty `redactions_by_reason` / `column_name_map`), chunk continuation (metadata `null`, slice of redactions). New `signalforge.safety.audit.read_audit_events(path) -> Iterator[AuditEvent]` helper reassembles chunked records by `audit_id`; end-of-stream partial groups surface a WARNING but don't raise. Empirical ceilings: single-line shape covers up to ~65 redacted columns; chunked shape covers ~66 – ~243; above ~243 the header chunk's `columns_sent` tuple overflows and `AuditRecordTooLargeError` raises. (Plan-design estimate of 170-col single-line was measured against the redactions-only payload; the full event also carries `columns_sent`, lowering the practical single-line ceiling.) `AuditRecordTooLargeError` gains a `column_count` field plus an operator-actionable three-sentence remediation pointing at `meta.signalforge.skip_draft: true` as the workaround and explicitly warning against `safety.mode: aggregate-only` (which does NOT shrink redactions). See `docs/safety-ops.md` § "Audit JSONL schema (v4)".
- **Grade-layer asyncio orchestrator: parallel per-`(artifact × criterion)` LLM dispatch (#186).** Closes the v0.2 deferral anticipated by `grade-layer.md`'s "One LLM call per (artifact × criterion); sequential — `asyncio.gather` deferred to v0.2". The grade engine now dispatches per-pair LLM calls concurrently via `asyncio.TaskGroup` + `asyncio.Semaphore(max_concurrent_calls)` + `asyncio.timeout(total_budget_seconds)`. New `GradeConfig.max_concurrent_calls: int = 10` knob (range `[1, 100]`, `extra="forbid"`; setting `1` reverts to v0.1 sequential behaviour bit-for-bit, including audit JSONL `(criterion, artifact)` ordering). Public `grade_artifacts(...)` signature unchanged — sync prefix → `asyncio.run(_grade_artifacts_async_core(...))` → sync suffix. Measured ~9× wall-clock reduction on a typical ~280-pair model (~70 artifacts × 4 criteria; ~280 s → ~30 s, close to the Amdahl ceiling at concurrency=10). Two new typed errors at orchestrator entry: `GradeNestedEventLoopError(GradeError)` (CLI tier 1) raises if `grade_artifacts(...)` is called from within a running event loop (v0.3 ships single-event-loop only; v0.4 follow-up will lift this); `LLMProviderAsyncUnsupportedError(LLMError)` (CLI tier 3) raises against any provider whose `LLMProvider.supports_async = False` — fail loud at orchestrator entry rather than silently degrading every pair (cap=1 is NOT an escape hatch: the engine consumes `call_llm_async` exclusively post-#186). All three v0.3 providers (Anthropic, OpenAI, Gemini) set `supports_async = True`. Provider-neutral sibling `signalforge.llm.call_llm_async(...)` mirrors the sync `call_llm` signature 1:1, with `_async_sleep = asyncio.sleep` module-level alias parallel to the existing `_sleep` / `_rand_uniform` (`llm-drafter.md` DEC-004). Per-vendor async client shims confined to their respective `_<vendor>_client.py` modules; AST scans 3b (`anthropic.AsyncAnthropic` only in `_anthropic_client.py`) and 9b (`openai.AsyncOpenAI` only in `_openai_client.py`) enforce the rule — total project AST scans 10 → 12. Gemini's async surface is `.aio` on the existing `genai.Client` so Scan 10 is untouched. Fake clients (`FakeAnthropicClient` / `FakeOpenAIClient` / `FakeGeminiClient`) gain a dual sync+async surface on the existing `expect_*` queue infrastructure — one class per vendor. New `pytest-asyncio>=0.23,<1` dev-dep with `asyncio_mode = "strict"` and registered `asyncio` marker. `ExceptionGroup` renderer in `signalforge.cli._helpers.format_error_to_stderr` (defence-in-depth — per-coroutine try/except inside the engine prevents grade-typed exceptions from forming groups; a stray non-grade exception still renders cleanly as the existing multi-bullet stderr shape). `tests/grade/_helpers.py::_sort_grade_events(...)` JSONL sort helper for tests that snapshot the audit JSONL (arrival-order under concurrent dispatch). Three new gated per-provider live async smoke tests (`tests/cli/test_e2e_anthropic_async_smoke.py` / `test_e2e_openai_async_smoke.py` / `test_e2e_gemini_async_smoke.py`) exercise concurrent dispatch against real providers behind the same env-var gates as their sync siblings. Audit-write wrapped in `asyncio.shield` (#186 QG Pass 1 BLOCKER fix) so a budget timeout during the executor await cannot produce duplicate JSONL records.
- **`row_count_anomaly_by_period` as the 8th first-class `CandidateTest` variant + `--as-of YYYY-MM-DD` flag for time-bound reproducibility carve-out (#171).** End-to-end coverage across drafter + prune + grade + diff (singular `tests/*.sql` emission, mirroring `custom_sql`); ingest deliberately not extended in v1 (no canonical dbt-utils / dbt-expectations macro). The drafter proposes this variant for incremental fact tables with a populated date partition column (`loaded_at`, `created_at`, `event_date`, `partition_date`), with `seasonality="dow"` recommended for business-calendar grains. Four statistical methods (`mad` default / `zscore` / `percentile` / `min_max`) × two seasonality knobs (`none` / `dow`) on a configurable lookback (`lookback_periods=28` default; tunable). **First time-bound test primitive — same SQL + same warehouse data + different `--as-of` may produce different decisions** because anomaly bands shift as history accrues; the new `--as-of YYYY-MM-DD` flag on `generate` and `prune-existing` restores reproducibility at the `(model, as_of)` granularity (when omitted, the engine resolves to `date.today()` and emits one INFO line naming the resolved value, which lands on every `PruneEvent.as_of` audit record). Prune evaluation is a two-query split (DEC-008): a stats query populates the typed `AnomalyTestStats` value-object (tagged-union: `MadStats` / `ZscoreStats` / `PercentileStats` / `MinMaxStats`) on `PruneDecision`; the violation query then runs only when `n_periods >= min_samples_per_bucket`. Cold-start (insufficient history) routes to `kept-without-evidence` with structured `why="insufficient history: <n>/<min> periods"` per the conservative-bias contract — no new `DropReason` literal. Thin-DOW degrade emits one WARNING line per test and proceeds without seasonality. The compiled SQL **always** includes a partition-pruning WHERE clause (DEC-012) so date-partitioned tables get the ~30× scan reduction (90-day lookback on a 1B-row daily-partitioned table: 9 GB unfiltered → ~300 MB partition-pruned); the existing `maximum_bytes_billed` cap remains the safety net. Sample-mode bypass is stricter than `row_count_between` / `unique_combination`: this variant **always** routes to source, even under `sample_strategy="oneshot"` — a hash-mod sample over a date-partitioned table does not preserve per-period counts (DEC-002). New `WarehouseAdapter.run_stats_query` ABC seam ships with a BigQuery override; non-BigQuery adapters inherit the ABC default raising `StatsQueryNotSupportedError`, which the prune engine catches and routes to `kept-without-evidence` (mirrors the `MaterialisationNotSupportedError` / `EstimateNotSupportedError` / `RowCountNotSupportedError` graceful-degrade pattern). Operators can suppress via `exclude_tests=["row_count_anomaly_by_period"]` in `signalforge.yml`.
- **`unique_combination` as the 7th first-class `CandidateTest` variant (#170).** End-to-end coverage across drafter + prune + grade + diff + ingest. The drafter proposes it as a structured candidate for models whose natural grain is a composite key — `(order_id, line_item_id)` on an order-line table, `(user_id, day)` on a daily activity rollup, `(start_station_id, end_station_id, trip_date)` on a trip-pairs aggregate — with the no-`where` and with-`where` JSON shapes both illustrated in the prompt catalogue and a cautionary `_UNIQUE_COMBINATION_SCOPE_INSTRUCTION` block steering the drafter away from vacuously-unique tuples like `(primary_key, anything)`; the prune compiler emits a multi-column `GROUP BY <cols> HAVING COUNT(*) > 1` (dialect-driven, BigQuery + Snowflake snapshots green) routed past the materialised-sample substitution to the source table (sample-mode false-negative bypass mirroring `row_count_between`); the grade rubric's existing `no-redundant` criterion is extended to score grain-meaningfulness for composite-key tuples (`(pk, anything)` shapes route to `flagged`, not a new degrade slot); the diff emitter renders kept artifacts as `{dbt_utils.unique_combination_of_columns: {combination_of_columns: [...], where: "..."}}` (null fields omitted); `prune-existing` ingest now recognises `dbt_utils.unique_combination_of_columns` from external `schema.yml` and promotes it to the typed variant — same shape as `expect_table_row_count_to_be_between` promotion from #169 (other `dbt_utils.*` macros continue to skip-record). Operators can suppress via `exclude_tests=["unique_combination"]` in `signalforge.yml`. The `args_hash` canonical form sorts the `columns` tuple before hashing (DEC-011) so `(a, b)` and `(b, a)` share one cache key — the GROUP BY result-row identity is column-order-invariant.
- **`dbt_utils.unique_combination_of_columns` ingest recognition (#170).** New parser arm in `signalforge.ingest.parser._parse_named_test` promotes the macro from `SkippedTest(reason="custom-or-generic-test")` to the typed `CandidateTestUniqueCombination` variant on `prune-existing` runs. Inbound mapping: `combination_of_columns` → `columns`, `where` → `where` (inverted by the diff emitter on outbound — round-trips to the same dbt-utils YAML). Malformed shapes (missing key, empty / `< 2` columns, duplicate items, non-string items, column-scoped usage, non-string `where`) route to `SkippedTest(reason="malformed-supported-test")`; the closed 3-value `SkipReason` literal stays locked. Operators without `dbt-utils` installed in their project will see a clear `dbt parse` error when applying the diff — there is no `.sql` fallback in v1, mirroring the `dbt-expectations` posture established in #169 (operators install the package or remove the test).

- **`signalforge.warehouse`** — `WarehouseAdapter` ABC + `from_profile` factory, `BigQueryAdapter` concrete, `load_profile` for dbt `profiles.yml`, deterministic hash-mod sampling with fail-loud sizing checks, `use_query_cache=False` default for reproducibility. (#3)

Includes the v0.2 temp-table-materialised sample optimisation (`prune.sample_strategy: materialised` default; opt-out to `oneshot` for non-BigQuery adapters). (#6, #22)

(#7)

### Architectural commitments locked

- Signal over volume — pruning is allowed to drop only with positive warehouse evidence; `kept-without-evidence` is a real outcome.
- Evaluation in the loop — every kept artifact gets a per-criterion grade with a one-line "why."
- Warehouse-agnostic by design — BigQuery-isms confined to `signalforge.warehouse.adapters.bigquery` + its `_client.py` shim; the ABC is dialect-neutral.
- OSS-first, Core-friendly — no dbt Cloud dependency; runs against any dbt-core project, locally or in CI.
- Explainable diffs — every kept/dropped/flagged artifact ships with a one-line "why"; every run produces a sidecar JSON with reproducibility hashes.
